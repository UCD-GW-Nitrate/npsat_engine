# Small shared-input flow verification

Run commands from the repository root. This folder contains actual portable
inputs, not generated references to another checkout. Build with deal.II 9.3,
MPI, Trilinos, p4est and Boost.Program_options:

```sh
cmake -S . -B build-flow -DCMAKE_BUILD_TYPE=Debug
cmake --build build-flow -- -j2
mkdir -p examples/shared_flow/output
build-flow/npsat -c examples/shared_flow/fixed.ini --validate-only
mpirun -np 2 build-flow/npsat -c examples/shared_flow/fixed.ini --print-config
mpirun -np 2 build-flow/npsat -c examples/shared_flow/scenario1.ini
mpirun -np 2 build-flow/npsat -c examples/shared_flow/moving.ini
mpirun -np 2 build-flow/npsat -c examples/shared_flow/sources.ini
```

Supply `-DDEAL_II_DIR=...` and `-DBOOST_ROOT=...` if necessary. Older CMake can
use `mkdir build-flow; cd build-flow; cmake ..` instead of `-S/-B`. No Python
is needed to run the executable. The optional regression harness requires Python 3.
Output is ignored by Git and repeated manual runs overwrite that case's outputs.
The harness instead refuses to overwrite an existing run directory.

| Configuration | Verification purpose |
| --- | --- |
| `fixed.ini` | Column 0: bottom head 10, initial top 12, K=1, recharge .001. Exact head `10+.001*z`, recharge total 10 |
| `scenario1.ini` | Same physical input files, column 1: bottom head 20, top 24, K=2, recharge .004. Exact head `20+.002*z`, recharge total 40 |
| `moving.ini` | Column 0, three solve/elevation-update cycles; top approaches approximately 10.01. Adaptive refinement disabled |
| `sources.ini` | Adds shared well/stream inputs using explicit legacy-well assembly: external well ID 17, extraction -.25, stream flux .0002 |
| `v2.ini` | Separate reference-solver configuration using the same physical files; full v2 flow execution is not a step-1 regression test |

The box is 100 x 100, bottom z=0, discretization 2 x 2 x 1 cells. The one-column
bottom and porosity tables demonstrate constant broadcasting. Other tables have
two columns. `grid`, `scatter` and `lateral` fixtures are used by the reader
comparison, not by the main constant-property solve. `neumann.dat` documents
the retained v1 grammar; it is not enabled in the analytic cases.
The stream's width field is a half-width: length 80 and half-width 10 give
area 1600 and applied stream inflow .32 for column 0.

The v2 file excludes v1-only FEM/Tracing options and supplies storage, initial
head and time-file metadata required by that reader. v2 geometry/time handling
and discretization must still be checked when extending this example to an
unconfined comparison. Do not interpret matching input readers as matching
numerical formulations or a validated full v2 solve.

## Repeat the tests

```sh
cmake -S tests -B build-flow-tests -DCMAKE_BUILD_TYPE=Debug
cmake --build build-flow-tests -- -j2
(cd build-flow-tests && ctest --output-on-failure)
python3 tests/shared_flow_tests.py --exe build-flow/npsat --output build-flow/shared-checks --reader build-flow-tests/shared_reader_probe
```

The suite copies this input directory into each test case, tests one/two MPI
ranks, verifies analytic solutions and step-0 fixed/moving references, and checks
nonzero exits for malformed inputs under MPI with a timeout. Each case retains
its generated INI, input files, run log and any numerical output. The final
`results.json` summarizes results. Choose a fresh `--output` directory to rerun.

To compare against a local v2 checkout without modifying it:

```sh
cmake -S tests -B build-reader-comparison -DCMAKE_BUILD_TYPE=Debug -DNPSAT_V2_REFERENCE=/path/to/npsat_v2_9_3/npsat_flow
cmake --build build-reader-comparison -- -j2
python3 tests/shared_flow_tests.py --exe build-flow/npsat --output build-flow/reference-checks --reader build-reader-comparison/shared_reader_probe --reference-reader build-reader-comparison/v2_reader_probe
```

`expected_reader.txt` was generated by the actual v2 headers at `trace_dbg`
commit `8e45fff22713b5e9cfde40face27f58f04f1ac00`, and matched the v1 reader output
exactly for both stress columns. It lets another PC compare against the pinned
reader result even without a v2 checkout. This checks interpolation, Dirichlet,
well geometry/rates and stream rates; it does not run the HMFEM solver.

The step-0 baseline comparison includes Float32 VTU precision tolerances. The
reference was generated with GCC 9.3/deal.II 9.3/Open MPI 4.0.3. Aqua/GCC 5
validation remains a deployment gate; archive its toolchain and results separately.
